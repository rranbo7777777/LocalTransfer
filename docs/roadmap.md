- Release APK 发布流程与手动签名说明；GitHub Actions iOS 打包工作流。

### 阶段 2：传输可靠性改造

针对"传着传着就失败"的根因（客户端只重试 3 次、总窗口不到 1 秒，服务端检查点形同虚设）逐条修复：

- 客户端续传闭环：每轮重拉 `missingChunks` 接着传，轮间探 `/api/v1/health`，预算 30 分钟，零进展 3 轮即止。
- 重试改为指数退避（250 ms × 3ⁿ，封顶 10 s，最多 5 次）。
- 单个文件失败不再中断整批；失败项可单独重试并显示原因。
- 传输可取消，取消会清理服务端残留。
- Kestrel 针对弱网与前后台切换调参（请求体上限、最小数据速率、空闲超时、并发连接）。
- 服务端每 IP 并发限制 12（429），回环豁免。

### 阶段 3：体验与可观测性

- **整批一次确认**：`POST /api/v1/batches`（挂起请求，≤500 文件），桌面 `BatchApprovalWindow` 支持逐文件取消勾选。
- **自动发现**：电脑组播公告（`224.0.0.167:53318`），手机按证书指纹自动找回电脑，换网络/换 IP 免扫码；
  发现不授予任何权限，首次配对仍需扫码。
- **双向历史**：`history.jsonl`（JSON Lines，500 条 / 512 KB 上限），记录点挂在状态机终态分支上。
- **诊断双端落地**：桌面 `logs/coordinator.log`（4 MiB 轮转），手机错误日志 + 主页导出分享。
- 桌面 UI 修正：列表行右侧元素对齐（`HorizontalContentAlignment`）、侧边栏版本号贴底（`LastChildFill`）、
  目标设备选择器重做、历史行状态徽标与失败原因 tooltip、页面标题与副标题与功能现状对齐。
- 真机日志驱动的两处修复：`UploadStaging` 一律复制到缓存（`content://` 不能被重复打开）；
  传输流程整体包进 `Task.Run`，避免 `await` 回到 UI 线程后 `HttpResponseMessage.Dispose()` 触发
  `NetworkOnMainThreadException`。

## 下一步：真机联调与可靠性验收

1. 在专用 Wi-Fi、电脑热点、手机热点三种拓扑中联调 Windows 与 Android。
2. 验证 Windows 防火墙提示、睡眠唤醒、Wi-Fi 切换、应用前后台切换。
3. 验证微信和 QQ 的单文件、多文件、图片、视频、文档分享入口。
4. 执行断网、重复请求、源文件变化、磁盘不足、哈希错误和应用崩溃恢复测试。
5. 完成 10 GB 单文件、100 文件批量、重名和零字节文件验收。
6. 自动发现的边界：组播被路由器过滤、多网卡/VPN 共存、同名多台电脑。
