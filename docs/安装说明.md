# 局域传输 · 实验版安装说明

产物构建日期：2026-10-18（第五次构建）。文档更新：2026-10-19。

**本次电脑端与手机端都有更新，且改动集中在传输本身，请两端同时替换。**

## 这一版改了什么

修的是"传着传着就失败"这一类问题：

- **断点续传真正生效**：以前任一分块连续失败 3 次（总窗口不到 1 秒）就放弃整个文件，而服务端其实一直存着已收到的分块却没人去续。现在失败后会自动重新查询缺失分块接着传，预算 30 分钟；Wi-Fi 断开再恢复也能自己接上。
- **重试改为指数退避**：250ms → 750ms → 2.25s → … → 10s（最多 5 次），短暂断网不再直接判死。
- **一个文件失败不再拖垮整批**：未成功的文件会留在列表里，可直接再点「发送」重试，并逐条说明失败原因。
- **可取消**：传输中新增「取消」按钮。
- **批量只确认一次**：一次选 100 个文件，电脑端只弹**一个**窗口列出全部文件，可全选 / 全不选，也可以取消勾选只拒绝其中某几个（单批上限 500 个）。
- **自动发现**：电脑端会广播自己，手机在同一 Wi-Fi 下自动找到它；**换网络或电脑换了 IP 都不用重新扫码**（首次配对仍需扫码）。
- **双向历史记录**：电脑「历史记录」页同时记录发送和接收，带设备名与失败原因（写在本机 `history.jsonl` 里，不再靠扫接收目录）。
- **手机端「导出诊断日志」**：主页底部新增按钮，出问题时把日志导出给开发者。

⚠️ **本次两端都要更新**：电脑端替换整个 `win-x64` 文件夹（不要只拷 exe）；手机端重装本目录的 APK（签名未变，可直接覆盖安装）。

> 提醒：关闭窗口只是收进托盘，**要真正退出请右键托盘图标 →「退出」**。
> 没退出就替换 `win-x64`，会因文件被占用而失败。

## 内容

- `win-x64/` — Windows 桌面版（自包含，无需安装 .NET）
- `局域传输-1.0-arm64.apk` — Android 手机版（arm64，Release 签名）
- `collect-phone-log.bat` — 抓手机日志的小工具（见文末故障排查第 8 条）
- iOS 版：见下方"iPhone 安装"

## 一、安装 Windows 端

1. 把 `win-x64` **整个文件夹**复制到任意位置（如 `D:\Tools\LocalTransfer`）。
2. 双击运行 `LocalTransfer.Windows.exe`。
3. 首次运行 Windows 防火墙弹出提示时，**勾选"专用网络"并允许**（家庭 Wi-Fi 属于专用网络；如果勾了"公用网络"或都勾会连不上）。
4. 点击「创建配对信息」，屏幕会显示二维码。

> 实测本机防火墙三个配置文件均处于关闭状态，所以连不上时通常不是防火墙的问题，优先怀疑路由器 AP 隔离或不在同一网段（见第 4 条）。

## 二、安装 Android 端

1. 把 `局域传输-1.0-arm64.apk` 传到手机（微信文件传输助手 / 数据线 / 网盘均可），点击安装。
2. 系统提示"未知来源应用"时，允许该来源安装。
3. 打开「局域传输」，点击「配对」→「扫描电脑二维码」，扫第一步的二维码。
4. 电脑上会弹出确认框，核对设备名后点「是」。
5. 扫码不可用时，也可在电脑上点「复制配对信息」，把内容发到手机，用「粘贴配对信息」完成配对。

> 第一次打开扫码页时手机可能会申请相机权限，**必须允许**，否则扫码会直接失败。

## 三、开始传输

- **手机 → 电脑**：手机端「选择文件」后点「连接电脑后发送」。电脑会弹**一次**窗口列出整批文件，确认后开始传输。也可在微信/QQ 里用「用其他应用打开 → 局域传输」分享。
- **电脑 → 手机**：电脑上选择目标设备、添加文件、点「发送」；然后手机保持打开应用，点「接收电脑发来的文件」主动拉取。
- 两台设备必须在**同一个 Wi-Fi**（或手机开热点给电脑）下，不能用访客网络。
- 传输出错时不必重新选文件：未成功的文件仍留在列表里，再点一次发送即可，已传的分块会被复用。

### 换了网络 / 电脑换了 IP

不用重新扫码。手机的「目标电脑」会自动更新——它进前台时会听 8 秒局域网广播，按配对时记住的证书指纹认出那台电脑。传输进行中不会切换地址，避免把正在传的连接打断。

如果等了十几秒仍显示"未连接"，见故障排查第 9 条。

## 四、iPhone 安装（通过 GitHub Actions）

iOS 的完整打包（原生链接、.app 组装）必须在一台 Mac 上完成，Windows 本机无法产出 ipa。本项目用 GitHub Actions 的 macOS 云服务器代替：

1. 打开仓库页面 https://github.com/rranbo7777777/LocalTransfer
2. 进入 **Actions** 标签页 → 左侧选择 **iOS打包** → 右侧点 **Run workflow** → 再点绿色 **Run workflow** 确认。
3. 等待约 15–25 分钟，构建完成后进入该次运行页面，底部 **Artifacts** 下载 `LocalTransfer-ios-unsigned`，解压得到未签名 ipa。
4. 用电脑给 iPhone 侧载（任选其一，均需免费 Apple ID 登录）：
   - **Sideloadly**（Windows 版）：手机连电脑，拖入 ipa，输入 Apple ID 开始签名安装。
   - **AltStore**：电脑装 AltServer，手机装 AltStore，在手机上通过 AltStore 安装 ipa。
5. 手机上首次打开需在 设置 → 通用 → VPN与设备管理 里信任你的 Apple ID 证书。

注意：

- 免费 Apple ID 签名的应用 **7 天过期**，过期后重新用 Sideloadly/AltStore 签一次即可；数据不丢。
- 电脑需安装 iTunes 和 iCloud（Apple 官网下载版，不是微软商店版）以便识别 iPhone。
- iOS 版是三个端里完成度最低的：代码从未在真机运行过，且微信/QQ 分享入口（Share Extension）尚未实现，目前只能用应用内文件选择器。
- 首次配对/传输时 iOS 会弹"本地网络"权限，必须允许，否则连不上电脑。

## 注意事项

- 接收的文件：电脑在 `下载\LocalTransfer`，手机在应用私有目录（接收完成后会询问是否打开系统分享/保存菜单）。
- 电脑端确认窗口在 **11 分钟内**有效，超时自动作废（手机端约等 10 分钟）。被忽略的提示会自己释放名额，不会像旧版那样攒满 10 个就再也发不出文件。
- **发送队列会持久化**（电脑端 `outbound-queue.json`），程序重启后仍在排队；但如果源文件被移动、改名或改动过，该条会被静默丢弃。
- 历史记录与配对信息存放在 `%LOCALAPPDATA%\LocalTransfer`，日志在其中的 `logs\coordinator.log`（设置页可一键打开）。
- 本版本仍为实验版，**尚未完成 10 GB 单文件 / 100 文件批量 / 断网恢复的真机验收**；遇到问题请记录现象（手机型号、Android 版本、报错文字），并按第 8 条抓日志。

## 签名信息

APK 使用自建密钥签名，密钥库位于仓库 `signing/localtransfer.keystore`，密码与别名见 `signing/keystore-info.txt`。**请妥善保管**：以后更新应用必须用同一密钥签名，否则手机需先卸载旧版（会丢失配对数据）。

## 故障排查

### 1. 手机扫码一打开就闪退，或报 `exception_wasthrown` / `java.lang.RuntimeException`

这是**旧版 APK 的已知缺陷**：`AndroidManifest` 里声明了相机权限，但 Android 6 起危险权限还必须在运行时申请，旧版从未申请，App 和扫码库都没做这一步。本版已改为打开扫码页前显式申请并给出提示。

- 确认已重装本目录的 APK。
- 若仍不行，检查：设置 → 应用 → 局域传输 → 权限 → 相机 是否为"允许"。
- 也可以**完全跳过扫码**：电脑上点「复制配对信息」，把内容发到手机并复制，再在手机 App 里选「配对 → 粘贴配对信息」。

### 2. 左侧导航栏的按钮点了没反应

这是**最早那版电脑端**的缺陷：导航栏里的「设备 / 传输任务 / 历史记录 / 设置」当时只是占位按钮，没有绑定任何动作。第三次构建已把它们全部做成真实页面。**电脑端必须整体替换 `win-x64` 文件夹**才会生效（只换 exe 不行）。

如果在「设备」页看不到你的手机，说明这台手机还没配对成功——回到「发送文件」，点「创建配对信息」重新扫码。

### 3. 电脑上"发送"按钮是灰的

灰显只说明两件事之一没满足：**没有已配对设备**，或**还没添加文件**。设备下拉框下方会实时提示当前缺哪一步。

第一次使用必须先点「创建配对信息」显示二维码，手机扫码并在电脑弹窗里点「是」，设备才会出现在下拉框里。

### 4. 手机连不上电脑

- 两者必须在**同一个 Wi-Fi**（或手机开热点给电脑），且不能用访客网络。
- 核对电脑窗口右上角显示的地址（形如 `https://192.168.x.x:53317`），手机所连 Wi-Fi 要在同一网段。
- 路由器若开启了 **AP 隔离 / 客户端隔离**，同一 Wi-Fi 下设备也会互相不可见，需要在路由器里关掉。
- 电脑本机防火墙当前三个配置文件均为**关闭**状态，因此不是防火墙拦截。
- VPN 可能让二维码选错网卡；本机目前只选到 WLAN 地址，正常。若地址看起来不对，先退出 VPN 再点「创建配对信息」。

### 5. 发送文件时报错 401，或提示「配对凭据已失效」

含义：**电脑不认可手机手里的配对凭据**。最常见的原因不是网络，而是**配对其实没有真正完成**：

- 手机扫码后只等待约 2 分钟。如果你在电脑上**过了这段时间才点「是」**，旧版本会把新凭据写进电脑，而手机早已停止等待、手里还是旧的（或者根本没有）凭据 —— 之后每次发送都是 401。**这与有没有移除设备无关。**
- 其次才是：在电脑的「设备」页把本机移除了；或这台手机在电脑上重新配对过。

处理办法：**重新配对一次** —— 点手机上的「配对」，扫电脑上的二维码（或点电脑的「复制配对信息」后用「粘贴配对信息」），然后**尽快**在电脑弹窗里点「是」。

第四次构建之后，这条链路被彻底堵上了：

- 电脑端：超时后再点「是」会明确告诉你"配对未完成"，不再静默写入凭据（这正是过去造成 401 的根因）；
- 手机端：遇到 401 会自动清除失效凭据、回到"未连接"，并提示重新配对；
- 手机端：配对失败（超时 / 被拒 / 二维码无效）时改用中文说明该怎么办，不再抛英文错误。

### 6. 手机发送时提示「电脑没有接收这次发送」

含义：电脑上的接收确认窗口**没有被点「是」**——要么点了「否」，要么一直没人点、到点自动失效了。

- 电脑上的确认窗口只在 **11 分钟** 内有效；手机自己等待约 **10 分钟**。手机超时会先说"电脑一直没有确认"，之后**重新发送**即可，不会留下垃圾文件。
- 旧版有一个隐患：被忽略的提示会**永久占位**。每台设备最多只能有 10 个待确认的发送，攒满之后那台手机就再也发不出东西，必须重启电脑端。本版已改为到点自动作废并释放名额。
- 文件要出现提示才开始传，所以**让电脑上「局域传输」保持运行**，并在看到提示后点「是」。

### 7. 手机接收电脑发来的文件时提示「存储空间不足」

含义：要保存文件的目录所在分区剩余空间不够（接收的文件保存在应用数据目录的 `Received` 文件夹）。

- 旧版有一个判定错误：它查的是手机的 **根分区 `/`**（一个很小的系统分区），而不是应用数据真正所在的 `/data`，所以在手机明明还有空间时也会报「空间不足」。**本版已改为按目标目录所在分区判断**，提示里还会给出所需与可用的字节数。
- 如果新版仍然这么提示，那就是手机确实快满了：清理空间后重新接收即可（同一台电脑重新发送时，已经收好的分块会复用，不会从头再来）。

### 8. 抓日志（排查任何疑难问题的第一步）

**手机端**：用数据线连上手机、打开「开发者选项 → USB 调试」并在手机上同意授权，然后**双击本目录的 `collect-phone-log.bat`**：

1. 它会先拉取 App 自己的错误日志；
2. 然后开始录制系统日志，此时在手机上复现问题；
3. 复现后回到黑窗口按 `Ctrl+C`，再按任意键退出。

把同目录生成的 `phone-errorlog.txt` 和 `phone-logcat.txt` 发回来即可定位。

也可以直接在 App 主页底部点「导出诊断日志」，把导出的文件发过来——这条路径不需要数据线。

App 错误日志在手机上的位置（也可用电脑"此电脑 → 手机 → 内部存储"直接拷贝）：
`Android/data/com.localtransfer.mobile/files/localtransfer-error.log`

**电脑端**：打开「设置」页点「打开」日志目录，取 `logs\coordinator.log`。里面记录了启动、发现广播、配对与每次传输的结果。

### 9. 换了 Wi-Fi 后手机一直显示「未连接」

先确认电脑上「局域传输」正在运行（托盘图标还在）。然后：

- 手机端把 App 切到后台再切回来，它会在前台重新监听 8 秒广播；也可点「刷新」。
- 部分路由器会**过滤组播**（尤其开启了"无线隔离"或 IoT 网络隔离）。这种情况下自动发现不会生效，但并不影响传输：在电脑上重新点「创建配对信息」再扫一次码即可，手机随后会用新地址连接。
- 电脑换了网卡（如插了网线又连了 Wi-Fi）时，广播会跟着实际选中的地址走；若地址选错，先在「设置」页确认服务地址。

### 10. 传输中断了，要不要重新选文件

不用。本版会把失败的文件留在待发送列表里：

- 源文件仍可读 → 直接再点「发送」，已传的分块会复用，从断点继续；
- 网络恢复后 30 分钟内都可能自动接上，不必手动操作；
- 连续多轮**一字节都传不动**时，程序会主动停下并报错——这通常意味着源文件没权限（比如从微信分享进来后授权已失效）或被移动了，重新选一次文件即可。
